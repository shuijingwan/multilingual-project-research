# 多语言覆盖缺口与上游替代风险评估规则

日期：2026-11-03
状态：RESEARCH_ONLY

## 一、背景

研究项目的目标语言范围固定为 66 门。

已有官方或第三方翻译，
不意味着该内容源没有商业机会。

go-dev 的实践表明：
即使已经存在部分社区语言版本，
仍可能通过扩大语言覆盖创造用户价值。

## 二、核心规则

不得仅因上游已有若干语言版本，
直接淘汰候选项目。

必须分别调查：

1. 官方已覆盖的目标语言。
2. 第三方已覆盖的目标语言。
3. 已有译文的完整性与维护情况。
4. 尚未获得优质覆盖的目标语言。
5. 上游历史语言扩张速度。
6. 上游未来多语言扩张计划。
7. 未覆盖语言的实际搜索需求。
8. 商业翻译授权及维护成本。

## 三、示例

假设一个项目已有 10 门官方语言，
而目标范围为 66 门语言。

其余 56 门语言可以成为调查对象。

如果上游长期没有扩展语言，
可能存在较长期的多语言供给缺口。

但不能据此直接推断：
- 56 门语言均有足够搜索需求；
- 官方未来不会增加翻译；
- 独立翻译站一定具有竞争优势；
- 广告收入能够覆盖维护成本。

上述结论均需证据。

## 四、上游替代风险

优先调查：

- 历史翻译增长速度
- 翻译贡献者活动
- 官方多语言路线图
- 自动化翻译能力
- 已有译文质量及更新情况

对未来 3～5 年的扩张预测，
缺少可靠证据时标记 UNKNOWN。

不得使用任意语言数量阈值，
机械淘汰候选内容源。

## 五、商业决策

同时考虑：

- 合法商业使用
- 长期内容价值
- 真实搜索需求
- 多语言供给缺口
- 上游替代风险
- 广告变现潜力
- 长期维护成本

语言覆盖数量不是最终成功指标。

最终目标仍然是长期广告净收益。

不启动翻译、网站开发或部署。
不修改 go-dev 项目。

## 六、有效语言覆盖与翻译竞争评估

### 6.1 基本原则

必须区分：

- 名义语言覆盖：项目宣称存在某语言版本。
- 实际内容覆盖：该语言具体翻译了哪些内容。
- 有效语言覆盖：已有译文在完整性、准确性、
  更新情况及可用性方面能否满足用户需求。

不得仅凭语言选择菜单、README 中的翻译链接、
社区项目列表，认定该语言已经完整覆盖。

不得因为已有第三方翻译，
直接认为新项目失去了竞争机会。

### 6.2 官方翻译与第三方社区翻译

调查时必须记录翻译主体：

- 官方维护
- 官方认可的社区维护
- 独立第三方社区维护
- 维护主体不明

官方身份不自动代表质量更好。

第三方身份也不自动代表质量更差。

翻译质量、完整性与维护状态必须分别核实。

### 6.3 内容范围检查

对于具有多个内容模块的项目，
必须逐模块检查实际翻译覆盖情况。

例如，以 go.dev 学习资源作为方法论示例：

- Tour
- Learn
- Documentation
- 首页与学习导航
- 其他正式研究范围内的内容

如果某第三方项目只翻译 Tour，
不能认为它已经完整翻译了全部学习资源。

即使已有同一种语言，
仍可能存在明显的内容覆盖缺口。

但不能未经调查就认定其他社区项目
实际只覆盖部分内容。

### 6.4 翻译质量与更新情况

调查以下方面：

1. 译文是否覆盖原始内容的完整范围。
2. 是否存在大量缺失章节。
3. 是否存在长期未更新的内容。
4. 是否与当前上游版本一致。
5. 专业术语是否准确、一致。
6. 是否有独立质量审核证据。
7. 页面导航、代码示例和学习体验是否完整。

缺少直接证据时必须标记 UNKNOWN。

不得仅凭翻译项目的年龄、
提交次数或维护主体判断实际翻译质量。

### 6.5 商业竞争影响

以下情况可能存在进一步调查的价值：

- 已有翻译但内容范围明显不完整。
- 已有翻译但长期落后于上游。
- 已有翻译存在经过证实的质量问题。
- 已有翻译只提供分散页面，
  缺少统一学习入口或必要功能。
- 部分目标语言没有可靠的完整译本。

上述情况只是潜在机会。

必须继续调查：

- 现有译本的搜索排名和外部链接优势。
- 新网站能提供的实际用户价值。
- 目标语言的真实自然搜索需求。
- 商业翻译授权及广告政策。
- 长期更新和质量审核成本。

不得把内容竞争优势直接等同于
搜索排名优势或广告收入优势。

## 七、后续调查记录字段

具体内容源应尽可能记录：

| 字段 | 说明 |
| --- | --- |
| locale | 既定 66 门语言之一 |
| translation_owner | 官方或社区维护主体 |
| source_scope | 上游正式内容范围 |
| translated_scope | 实际翻译内容范围 |
| completeness | COMPLETE、PARTIAL 或 UNKNOWN |
| upstream_version | 核实的上游版本 |
| translation_version | 译文对应版本 |
| update_status | CURRENT、STALE 或 UNKNOWN |
| quality_evidence | 质量审核依据或 UNKNOWN |
| search_competition | 搜索竞争证据或 UNKNOWN |
| verified_at | 核实日期及来源 |

COMPLETE 必须有完整范围的证据。

PARTIAL 必须有明确缺失内容的证据。

STALE 必须有版本或内容差异证据。

没有证据时不得猜测。

初筛可以先抽查关键语言及模块；
深入调查再核对固定的 66 门目标语言。

## 八、对选题决策的影响

不能机械使用：

目标语言数 - 已有翻译语言数

作为实际市场缺口。

已有翻译的语言，也可能因为内容不完整、
质量问题或更新滞后而存在机会。

但同样不能因为存在这些可能性，
就预先认定新项目具有竞争优势。

最终仍应同时满足：

- 商业翻译授权清晰。
- 内容具有长期用户价值。
- 存在可验证的有效覆盖缺口。
- 具有合理的自然搜索需求。
- 能够控制长期维护成本。
- 具备合法广告变现的条件。

本规则适用于全部候选领域。
