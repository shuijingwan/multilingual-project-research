# go-dev 多语言工程经验跨项目复用评估

核实日期：2026-11-03
状态：RESEARCH_ONLY
性质：工程能力调查，不是执行规范

## 一、目的

识别 go-tour-i18n 中可能复用于未来多语言项目的能力。

本文件不复制原项目的完整工程规范，
不创建第二套翻译体系，
不授权启动任何新项目。

## 二、经验来源

原项目：
https://github.com/shuijingwan/go-tour-i18n

主要原始文档：

- docs/TRANSLATION_WORKFLOW.md
- docs/SITE_V2_WORKFLOW.md
- docs/NEW_LOCALE_RUNBOOK.md
- docs/LOCALE_ROADMAP.md

原始工程规则仍以 go-tour-i18n 为准。

## 三、可复用能力初步清单

| 能力 | 复用潜力 | 主要限制 |
| --- | --- | --- |
| 统一术语管理 | 高 | 不同领域需要不同术语体系 |
| Generation 与 Reviewer 隔离 | 高 | 需验证质量和执行成本 |
| 独立质量审核 | 高 | 审核标准依内容类型调整 |
| 精确内容单元及保护机制 | 中高 | 需要适配新的内容格式 |
| 上游变化检测 | 高 | 依赖来源的更新机制 |
| 增量重译与影响分析 | 高 | 需验证成本收益 |
| 内容完整性检查 | 高 | 内容结构因项目而异 |
| 多语言 SEO | 中高 | 需按市场与内容类型调整 |
| 静态网站构建与部署 | 中高 | 不同项目技术要求可能不同 |
| Go Tour 交互练习 | 低 | 明显具有 Go 专用特征 |

以上均为初步工程判断，
不是新项目上的实测结果。

## 四、不应直接复用的内容

- Go Tour 专用运行时及 Playground。
- Go 源码与示例专用解析规则。
- Go 项目的具体 CLI 和内部 Schema。
- 仅为历史迁移构建的兼容机制。
- 特定网站的部署域名与配置。
- 特定批次、模型和 Reviewer 会话身份。

不得把 go-dev 的全部工程复杂度
强加给未来的简单内容项目。

## 五、商业研究中的用途

评估具体候选项目时，记录：

1. 可直接复用的能力。
2. 需要适配的内容解析及质量机制。
3. 新增开发工作量。
4. 长期维护工作量。
5. 工程复用能够节省的时间。
6. 复用是否引入不必要的复杂性。

未经实际验证的成本保持 UNKNOWN。

工程复用能力是商业评估输入，
不是选择某个项目的充分理由。

## 六、未来工程资产的存放原则

当前：
- 原始工程规范保留在 go-tour-i18n。
- 本研究仓库仅保留复用能力和成本评估。

只有第二个正式项目获得授权，
且实际出现跨项目共同需求时，
才考虑提炼独立通用工作流或共享代码。

不得为了可能存在的未来需求，
提前开发第二套完整翻译工程。

## 七、当前结论

保留 go-dev 的成熟工程经验，
但不提前决定未来项目的实现架构。

未来项目仍以用户价值、合法授权、
自然搜索需求、广告净收益
及维护成本作为主要决策标准。

不修改 go-tour-i18n。
不启动翻译、部署或新工程。
